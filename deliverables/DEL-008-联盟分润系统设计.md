> 版本：v1.0（2026-11-27）｜目标：把现有的"好友订阅双方 +1 个月" referral 机制，升级为**服务端可归因、可对账、可结算**的分润体系。

## 1. 分润模型对比与推荐方案

### 1.1 三模型横向对比

| 维度 | 现金佣金 | 免费时长 | 混合（推荐） |
|---|---|---|---|
| 直接成本 | 佣金额（如首年 $20）真金白银流出 | 边际成本≈0（软件复制成本近零） | 可控：默认免费时长，现金按需开启 |
| 激励强度 | 高（可量化、可提现，适合 KOL/联盟客） | 中（对已认可产品价值的用户有效） | 高 + 分层：普通用户给时长，专业推广者给现金 |
| 合规复杂度 | **高**：涉及税务申报、代扣代缴、反洗钱/地区限制 | **低**：属产品权益，非现金支付 | 分层隔离，现金部分单独合规 |
| 前置条件 | PayPal Payouts 权限 / 手动付款流程 / 收款人信息 | 无，服务端改订阅到期时间即可 | 分阶段：阶段 A 零前置，阶段 B 再申请 |
| 欺诈风险 | 高（自买、退款套利、虚假交易） | 中（自买刷时长） | 同一套归因与反作弊规则复用 |
| 对账难度 | 高（需银行/支付流水 + 税表） | 低（订阅表即账本） | 佣金账本统一记录，按结算方式分流 |
| 法律红线 | 需明确"推荐费/佣金"性质与税务处理 | 需在服务条款中写明"赠送时长不可兑现" | 现金条款**需创始人确认**后生效 |

### 1.2 推荐方案：混合 + 分两阶段

- **阶段 A（立即，P0/P1 可交付）**：免费时长分润。推荐人每带来 1 个**已付款且过退款窗口**的用户 → 双方各 +1 个月 Pro（`subscriptions.expiresAt` 加 1 个月）。零现金流出、零支付权限依赖。
- **阶段 B（需申请 + 需创始人确认，P2）**：现金佣金。仅对"认证联盟伙伴"开放（人工审核/邀请制），首年 20%，走 PayPal Payouts 或手动转账。
- **分层理由**：免费时长激励普通用户，现金激励专业推广者；两者共用**同一套归因与佣金账本**（`commissions` 记录 `amount` 同时记录 `rewardType: FREE_MONTHS | CASH`），未来切换结算方式不需要重做归因。

> ⚠️ **需创始人确认**：是否真的开启现金分润、佣金比例、结算周期、提现门槛、适用国家/地区、税务处理方式。本文给出的是**可执行默认值**，不是已生效的商业条款。

## 2. 归因机制：`referral code` 贯穿全链路

### 2.1 五阶段链路与载体

```
① 分享     前端生成/服务端签发 code → 链接 ?ref=AGI-A1B2C3
② 点击     落地页读 ?ref= → 事件 referral_click + 写入 localStorage agi_ref_code
③ 注册     trial_start / onboard_complete 事件携带 refCode（与 clientId 绑定）
④ 付款     /api/subscription/create 把 refCode 编入 PayPal custom_id
           Webhook 验签后解析 custom_id → 得到 clientId + refCode
⑤ 分成     Webhook 写 commissions 记录 → 过 holdUntil → 进入可提现余额
```

**关键工程判断**：
- `/api/event` 的 `data` 是 free-form（server.js:343），**无需改 schema** 即可携带 `refCode`。
- 付款环节是归因断点：`custom_id` 当前只有 `clientId`，**必须扩展编码**才能让 Webhook 同时拿到推荐码。
- 一次性付款链接**无法携带 `custom_id`**（`PAYMENT_UPGRADE.md` 已确认），因此**只有 Subscriptions API 路径能自动归因**；一次性链接走 `/api/claim` 时需在认领表单加 `refCode` 字段做兜底归因（P1）。

### 2.2 `custom_id` 编码规范（新增，核心改动）

格式：`v1|<clientId>|<refCode>`，总长控制在 ≤64 字符（沿用现有 `slice(0,64)` 约束）。

| 场景 | custom_id 示例 | 说明 |
|---|---|---|
| 自然流量 | `v1\|c_z9y8x7w6vu54\|` | 无推荐码，尾部为空 |
| 推荐流量 | `v1\|c_z9y8x7w6vu54\|AGI-A1B2C3` | 可归因 |

服务端新增解析器（建议放在 `server/server.js` helpers 区）：

```js
// 解析 v1|clientId|refCode；兼容旧的单值 custom_id
function parseCustomId(raw) {
  const s = String(raw || '');
  if (!s.startsWith('v1|')) return { clientId: s.slice(0, 64), refCode: '' };
  const parts = s.split('|');
  return {
    clientId: String(parts[1] || '').slice(0, 64),
    refCode:  String(parts[2] || '').slice(0, 16).toUpperCase(),
  };
}
```

> ⚠️ **回归风险**：`planFromResource()`（server.js:219-226）当前从 `custom_id` 文本里找 `annual`/`monthly` 判断套餐。改成 `v1|...` 后该文本判断会失效，**必须依赖 `amount` 或 `plan_id` 兜底**（现有代码已有 `amount >= 100 / >= 15` 兜底，需测试确认）。这是上线前必查项。

### 2.4 归因窗口与冲突规则

| 规则 | 默认值 | 理由 |
|---|---|---|
| 点击→注册归因窗口 | 30 天 | `agi_ref_code` 存 localStorage，覆盖直到过期 |
| 注册→付费归因窗口 | 90 天 | 给犹豫用户足够时间；超过不计佣 |
| 归因模型 | **首触（first-touch）锁定** | 用户首次点击的 code 即锁定，后续其他 code 不覆盖；防"最后点击截胡" |
| 同一推荐人重复付费 | 仅**首年首笔**计佣（年付计 1 次；月付最多计 12 次） | 防无限续费套利 |
| 推荐人 code 不可输入自己的 | 前端 + 服务端双重校验 `refCode.ownerClientId !== clientId` | 防自买 |
| code 签发 | 服务端签发并落 `referrals`（取代前端随机） | 前端随机码服务端无法验证、可被伪造 |

## 3. 佣金规则（默认值，**需创始人确认**）

| 项 | 默认规则 | 备注 |
|---|---|---|
| 佣金比例 | 首年 **20%**（年付 $100 → $20；月付 $15 → $3/期，最多 12 期） | **需创始人确认** |
| 免费时长等价 | 每成功推荐 1 人：推荐人 +1 个月、被推荐人 +1 个月 | 与现金二选一或并行，取决于 rewardType |
| 结算周期 | 月度结算：次月 15 日前结算"上月已过 holdUntil"的佣金 | 给出对账窗口 |
| 佣金冻结期 (hold) | 付款成功后 **30 天**（覆盖 DEL-005 退款窗口） | **需创始人确认**（须与退款政策一致） |
| 最低提现额 | **$50**（或等值免费时长 3 个月） | **需创始人确认** |
| 佣金有效期 | 产生后 12 个月内须申请结算，逾期作废 | 防账本无限膨胀 |
| 自买 | `referrerClientId === refereeClientId` → 不计佣；同 payer email 命中推荐人收款邮箱 → 不计佣 | 见 3.1 |
| 退款追回 | 触发退款事件 → 对应佣金 `status=CHARGEBACK`，扣回余额；已支付则转负余额抵扣后续 | 见 3.2 |
| 取消订阅 | `BILLING.SUBSCRIPTION.CANCELLED` 仅回收权益，是否追回**已过 hold 的佣金**需创始人确认 | 保守默认：hold 期内取消则追回，过后不追 |

### 3.1 防作弊细则

- **自买**：服务端在生成 `commissions` 前校验 `referrerClientId !== refereeClientId`。
- **同人判定**：推荐人在 `/api/referral/me` 提交收款邮箱后，落 `referrals[code].payoutEmail`；Webhook 若发现 `subscriber.email_address` 与该邮箱相同 → 标记 `SUSPECT_SELF_DEAL`，需人工审核。
- **批量刷单**：同一 `refCode` 在 24h 内产生 >N 个新 `clientId`（N 默认 5，**需创始人确认**）→ 全部佣金转 `PENDING_REVIEW`。
- **风控数据边界**：**不记录原始 IP**；若必须风控，仅记录一次性 hash 或粗粒度地区，且须在隐私政策（DEL-005）中披露。本系统遵守"后端只记匿名 clientId"的现状约束。
- **code 暴力枚举**：`AGI-` + 6 位字符集约 21 亿组合，配合服务端签发 + `referrals` 白名单校验，未注册 code 直接忽略，不做归因。

### 3.2 退款追回流程

```
PayPal 退款 Webhook（如 PAYMENT.CAPTURE.REFUNDED / PAYMENT.SALE.REFUNDED）
  → 用 orderId / sale id 关联 sourcePayment.orderId
  → 找到对应 commissions
  → status = CHARGEBACK，ledger 追加 { ts, action: 'REFUND_CLAMP', amount: -20 }
  → 重算 referrer 可提现余额 = SUM(PENDING 已过hold) - SUM(CHARGEBACK) - SUM(已支付)
  → 若为负 → 记入 negativeBalance，后续佣金优先抵扣
```

> ⚠️ 退款事件的确切 `event_type` 需在 PayPal 后台 Webhook 订阅页核对并以官方文档为准；现有代码仅订阅了成功类事件（`server.js:535`、`567`、`604`），新增退款事件需一并配置 Webhook 订阅。

## 4. PayPal 结算路径与降级方案

### 4.1 Payouts API 的现实约束（**需额外申请**）

PayPal Payouts 是官方批量付款能力。基于公开开发者文档的概括性描述（**具体费率、限额、支持国家/地区清单以 PayPal 官方后台与最新文档为准，本方案不写死数字，需创始人登录后台核实**）：

| 约束 | 说明 | 影响 |
|---|---|---|
| 开通门槛 | 通常需要商业账户、提交申请并通过审核 | 新账户**不能立即使用** |
| 资质/KYC | 需完成身份认证与业务信息核验 | 需创始人本人提交资料 |
| 地区限制 | 收款人所在国家/地区需在支持范围内 | 部分国家推广者无法收款 |
| 资金与限额 | 存在单笔/批量金额上限、资金来源与余额要求 | 大额或密集结算需分批 |
| 合规审查 | 付款用途、收款人信息需符合平台政策 | 可能被要求补充材料或延迟 |
| 税务 | 平台可能需收集税表/申报推荐费 | 见第 6 节 |

**结论：Payouts 属于"需额外申请"，不能假设上线即有，必须准备降级路径。**

### 4.2 降级方案（按优先级）

| 优先级 | 方案 | 能立即做？ | 说明 |
|---|---|---|---|
| 降级 1 | **免费时长**（默认） | ✅ 能立即做 | 服务端改 `subscriptions.expiresAt`，零现金、零权限依赖；作为现金未开通期间的默认权益 |
| 降级 2 | **手动 PayPal 转账 / PayPal.me** | ✅ 能立即做 | 创始人在 PayPal 后台按 `payouts` 审批列表逐笔付款；凭证回填 `paypalTxnId`；人力成本随规模上升 |
| 降级 3 | **礼品卡 / 等价权益** | ⚠️ 需确认 | 需选定礼品卡供应商与合规口径，**需创始人确认**是否可用 |
| 正式 | **PayPal Payouts API** | ❌ 需额外申请 | 开通后对接 `POST /v1/payments/payouts`，批次 ID 回填 `paypalPayoutBatchId` |

**降级不降级归因**：无论哪种结算方式，`commissions` 账本与归因链路完全一致，仅 `payouts.method` 与最终付款动作不同——这是"混合方案"最大的工程收益。

## 6. 合规与税务（诚实说明，**需创始人确认**）

- **现金分润性质**：推荐费/佣金通常构成收款人的应税收入；平台方可能承担代扣代缴、信息申报或出具税表的义务，**具体取决于创始人及推荐人所在司法管辖区**。本设计**不作法律结论**。
- **需创始人确认清单**（现金分润生效前必须逐项拍板）：
  1. 是否开启现金分润（阶段 B 的总开关）；
  2. 佣金比例 20%、最低提现额 $50、hold 30 天、结算周期；
  3. 适用国家/地区与不服务地区名单；
  4. 推荐费的法律定性（佣金 / 推荐费 / 其他）与合同文本（更新服务条款）；
  5. 税务：是否代扣、是否收集 W-9/W-8 等表单、由谁申报；
  6. 退款/取消订阅的佣金追回口径；
  7. 礼品卡方案是否采用。
- **隐私边界**：现有后端只有匿名 `clientId`；现金结算必须新增收款邮箱与可能的税表信息，**需在隐私政策（DEL-005）中披露并取得用户同意**，不得悄悄收集。
- **默认安全姿势**：在创始人确认前，系统**默认只发放免费时长**（`rewardType = FREE_MONTHS`），现金佣金记录即使产生也保持 `PENDING`，不进入可提现余额、不触发任何付款。
- **建议**：涉及跨境付款与税务时，请创始人咨询所在地专业税务/法律人士；本设计不替代专业意见。
