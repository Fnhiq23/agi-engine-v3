# AGI Engine 付费转化深度优化方案

> 基于 2026-11-27 线上真实状态：`/api/event` 漏斗埋点、`/api/report` 报表、PayPal 订阅链路已打通，但 `proClicks` 极少、付款为 0。
> 本方案只优化「转化」这一个可控变量，不承诺流量、不承诺收入、不改变实际价格（年付 $100 / 月付 $15）。
> 所有建议均可回滚、可证伪；涉及退款的表述一律标注「需创始人确认后执行」。

---

## 0. 第一性原理：付费到底是怎么发生的

把「用户付款」拆到不能再拆，它只是三个力合成的结果：

```
转化成付款 = 感知价值(Value) × 信任(Trust) − 摩擦(Friction) − 感知风险(Risk)
```

- 任何一步流失，都能归因为三种失败之一：**价值没被感知 / 阻碍没被清除 / 风险没被逆转**。
- 用户付的不是「功能」，而是「一个更满意的自己的状态」，并且要相信「钱付出去、东西真能拿到」。
- 因此本方案的顺序是：**先修价值认知（§1–3）→ 再修风险与摩擦（§4）→ 最后用实验验证（§5）**，文案是载体（§6）。

> **最关键洞察（先说结论）**：`proClicks` 极少，说明瓶颈**不在付款按钮**，而在更上游——用户还没感知到「值得付费的理由」，就被要求付 $100。付费墙目前卖的是「无限聊天 + 无限记忆」，但聊天质量取决于用户**自带 API Key**，演示回复为脚本；价值主张与真实体验错配，这才是一切实质流失的根因。修标题和价格呈现只能拿边际收益；真正的杠杆是让免费体验先创造 Aha moment（存下第一条真实记忆、感受到本地加密的安心），再让付费墙作为「留住它、支持它继续存在」的解法出现。

## 1. 转化漏斗诊断（逐环节流失点 + 心理分析）

漏斗链路：`落地页浏览 → 免费体验 → 激活 → 付费墙浏览 → 点击付费 → 完成付款`
对应现有埋点：`landing_view → trial_start → first_memory / first_chat → pro_view → pro_click → payment(PayPal Webhook)`。

### 环节 1｜落地页 → 免费体验

**当前可能的流失点**
- 首屏 headline 硬编码英文（`pw_headline`："Own an AI that actually remembers you."），产品标榜 14 种语言，但首屏未做语言自适应，非英语用户 3 秒内看不懂。
- 「需自带 LLM API Key」这一**关键前提成本**没有前置到首屏；用户进入免费体验才发现要配置，产生「被诱导」的心理落差。
- 没有明确的「下一步动作」承诺阶梯——落地页直接抛功能，缺少让用户做出一个小承诺（先体验）的引导。

**第一性原理心理**
- **注意力是零和稀缺资源**：首屏 3 秒内用户用「最省力路径」判断「这跟我有什么关系」，看不懂就离开。
- **承诺一致性阶梯**：人更愿意先接受小请求（免费试用）再接受大请求（付款）；顺序颠倒会触发防御。
- **诊断**：proClicks 极少，很可能从这里就开始流失——**到达付费墙的人本来就少**。

### 环节 2｜免费体验 → 激活（`first_memory` / `first_chat`）

**当前可能的流失点**
- Aha moment 太晚：用户要先存记忆/聊一次才感知价值，但 BYOK（自带 Key）门槛让首次对话受阻。
- 演示回复为脚本，一旦用户察觉「不是真智能」，信任瞬间崩塌——这是**负向峰值体验**。
- 免费额度（10 memories / 20 messages）若过早触发限制，用户感受是「被限制」而非「被帮助」。

**第一性原理心理**
- **禀赋效应**：用户只有在工具里**存下自己的记忆**后才会珍视它；没存就遇限制，禀赋效应无从建立。
- **峰终定律**：第一次体验的峰值（成功存下一条加密记忆 / 一次高质量对话）决定用户对产品的整体记忆。
- **诊断**：必须把 Aha moment 前置到付费墙之前——**先让用户「拥有」，再要求他付费**。

### 环节 3｜激活 → 付费墙浏览（`pro_view`）

**当前可能的流失点**
- 前端代码中未见 `pro_view` 的主动调用，存在**埋点漏报**风险——报表里的低数字可能是假象。
- 付费墙入口位置偏下（位于功能说明之后），用户可能根本滚动不到。
- 免费层已能满足轻度需求，用户**没有遇到真实阻碍**，付费动机为零。

**第一性原理心理**
- **需求触发**：付费不是被「推销」出来的，而是用户遇到真实阻碍时的自然解法。免费层若已足够好，付费墙就是「打扰」而非「解法」。
- **诊断**：要让阻碍真实存在且被感知（免费记忆满、想长期保留、想导出更多），此时付费墙才是「解法」。

### 环节 4｜付费墙浏览 → 点击付费（`pro_click`）★ 当前最严重

**当前可能的流失点**
- **价值-价格错配（根因）**：Pro 卖「无限聊天 + 无限记忆」，但聊天质量取决于用户自己的 API Key；理性用户会问「我为什么要为脚本回复 + 自己付的 API 费用，付 $100？」
- **锚点不可信**：`$180` 划线无来源说明，精明用户判定为「先提价再打折」，反而损害信任。
- **功能空洞**：`Priority compute resources` / `Task marketplace` 在纯前端、无后端的架构下缺乏支撑，技术型用户（本品核心受众）会识破。
- **支付痛感**：$100 一次性支付，属于「现金级痛感」；且页面同时给出月付 $15，未形成清晰的默认选择。

**第一性原理心理**
- **损失厌恶**：付款被大脑编码为「确定的损失」。必须让「不付费的损失」（隐私暴露、记忆无法长期保留、开发者无法持续维护）更突出。
- **锚定效应**：用户看到的第一个数字决定后续所有判断——不可信的锚点比没有锚点更糟。
- **交易效用**：用户算的是「我到底买到什么」，不是「你标价多少」。
- **诊断**：这是主战场。核心矛盾是**真实价值（本地加密记忆 + 隐私）与售卖话术（无限 AI 能力）不一致**。

### 环节 5｜点击付费 → 完成付款（Webhook 确认）

**当前可能的流失点**
- 跳转到 PayPal 外部页面造成**心理断裂**：用户在支付页重新决策，中断率天然高。
- PayPal 登录 / 绑卡摩擦；早期「手动开通权限」模式让用户担心「付了钱没人理」。
- 订阅状态仅存本地浏览器，跨设备不同步——诚实说明不足会变成事后争议。

**第一性原理心理**
- **风险厌恶**：陌生创作者 + 一次性 $100 = 高感知风险；这是**风险逆转**唯一能发挥作用的环节。
- **心理账户**：用户会把「给独立开发者的支持」归入「捐款」账户而非「购买软件」账户——需明确这是购买服务，不是捐赠。
- **诊断**：用 PayPal 官方买家保护 + 人工退款通道（需创始人确认后执行）+ 透明的开通流程来对冲。

## 2. 价值主张重构：3 个 A/B 标题变体（中英对照）

> 替换位置：`index.html` 的 `pw_headline` / `pw_sub`。三个变体分别测试三种心理杠杆，不要同时上线。

### 变体 A｜损失厌恶 + 隐私身份认同

- 中：**「别把你的记忆交给云端。把它们留在自己的设备里。」**
- 英：**"Don't hand your memories to the cloud. Keep them on your own device."**
- 心理学原理：**损失厌恶**——把框架从「付费获得隐私」翻转为「不付费就继续暴露隐私」，让「不行动的损失」变得 salient；**身份认同**——让「重视隐私的人」成为一种可归属的身份，付费成为身份表达而非消费。
- 预期影响环节：付费墙浏览 → 点击付费。

### 变体 B｜对比效应 + 独立开发者身份认同

- 中：**「一个属于你、会记住你的 AI——由独立开发者打造，不靠广告和你的数据赚钱。」**
- 英：**"An AI that's yours and remembers you — built by an independent maker, not funded by ads or your data."**
- 心理学原理：**对比效应**——与「靠数据变现的大厂」形成隐性对比，抬高本品价值；**身份认同 / 支持本地创作者**——把付款重构为「支持独立开发」的身份表达，这类支付痛感显著低于纯消费。
- 预期影响环节：落地页 → 免费体验、付费墙浏览 → 点击付费。

### 变体 C｜承诺一致性 + 先体验后付费

- 中：**「先用免费版把记忆存下来。真的离不开了，再支持它。」**
- 英：**"Start free. Save what matters. Support it only when you can't live without it."**
- 心理学原理：**承诺一致性**——先引导小承诺（免费存记忆），累计禀赋效应后再引导大承诺（付费）；**降低感知风险**——「先体验再决定」把付费决策点后移到体验之后，消除「付了才发现不合适」的恐惧。
- 预期影响环节：落地页 → 激活、付费墙浏览 → 点击付费。
- 注意：此变体与现有 `cta_why`（"Try free first — pay only if it clicks"）同向，需合并呈现，避免重复。

## 3. 定价心理学：2 个可测试的呈现优化（不改实际价格）

> 红线：年付仍为 $100、月付仍为 $15，只改**呈现方式**。

### 优化 A｜分母效应：把 $100/年 改写为 $8.33/月、$0.27/天

**现状**：价格块主视觉是 `$100`（大号），`$8.33/mo` 只是小字附注——把大数放在最显眼处，最大化了支付痛感。

**建议呈现**：
```
$8.33 / 月          （主视觉，最大字号）
按年支付 $100 · 平均每天 $0.27
```
- 心理学原理：**分母效应 / 心理分账**——把一次性大额拆成「每天一杯水都不到」的小单位，显著降低支付痛感；锚定从「$100 支出」转移到「$0.27/天」。
- 保持不变：$100 仍需可见（透明），只是不再占据主视觉。

### 优化 B｜可信锚点：把 $180 从「无来源划线」改为「$15 × 12 的算式」

**现状**：`$180 /year if paid monthly` 划线 + `Save $80 (44%)`——用户不知道 $180 怎么来的，可疑。

**建议呈现**：
```
按月付满一年 = $15 × 12 = $180
按年付一次 = $100（省 $80，相当于免费约 5 个月）
```
- 心理学原理：**可验证锚定**——把锚点变成用户能自己算出来的真实等式，锚定效应成立且不损伤信任；**比例偏见规避**——用「免费约 5 个月」替代抽象的「44%」，具体收益比百分比更有说服力。
- 保持不变：$180 的锚点数值与 44%/省 $80 的算法都不变，只是把算法显性化。

> 可选项（需先核实、慎用）：与「同类 AI 助手公开月费 $20–30 且不含本地隐私」做对比。只能在可引用公开定价且注明「以各产品公开页面为准」时使用，否则不要写，避免引入不实风险。

## 4. 风险逆转机制：3 个降低付款顾虑的具体设计

> 原则：只用真实存在的机制，不伪造承诺。退款相关一律标注「需创始人确认后执行」。

### 4.1 「7 天不满意可申请退款」——仅作为人工通道，不作为自动承诺

- **文案**：`试用 7 天，不满意可联系创始人申请退款（需创始人确认后执行，非自动退款）。`
- **英**：`Try it for 7 days — if it's not for you, contact the maker to request a refund (subject to the founder's confirmation; not an automatic refund).`
- **可执行性**：PayPal 交易本身提供**买家保护 / 争议通道**（这是官方真实机制）；在付费墙注明「付款后 7 天内可申请，人工审核」，既降低顾虑又不承诺自动到账。
- **边界**：不得写成「无条件退款」「自动退款」「7 天全网退」；必须在文案中保留「需创始人确认后执行」。
- **落地成本**：零开发，只需在付费墙加一行说明 + 创始人邮箱/联系入口。

### 4.2 PayPal 买家保护说明（引用官方真实机制）

- **文案**：`通过 PayPal 付款，符合条件的交易受 PayPal 买家保护（以 PayPal 官方条款为准）。`
- **英**：`Pay with PayPal — eligible transactions are covered by PayPal Buyer Protection (subject to PayPal's official terms).`
- **可执行性**：PayPal Buyer Protection 是官方公开政策，引用不构成虚假承诺；加「以官方条款为准」「符合条件」两个限定词，精准且合规。
- **落地成本**：零开发，一行说明 + 官方文档链接（`developer.paypal.com` 官方 FAQ 中已有买家保护说明）。

### 4.3 先体验后付费 + 透明的开通流程

- **设计**：把现有 `Try free first — pay only if it clicks` 从按钮下方**上移到价格块之前**，并在旁边补一句真实说明：
  - 中：`免费版就够用就别付。付费是为了支持持续开发，并解锁无限本地记忆。`
  - 英：`Stay on the free tier if it's enough. Paying supports ongoing development and unlocks unlimited local memory.`
- **配套**：明确写出「付款后如何拿到 Pro」——当前是**人工开通**（付款通知 → 创始人手动开通 / 提供兑换码），如实写明「付款后通常在一个工作日内开通」，比含糊承诺更能降低焦虑。
- **边界**：必须同步如实注明「订阅状态目前只存于此浏览器，跨设备同步需后端」——这是现有透明区已写明的真实限制，前置说明可避免事后争议。
- **落地成本**：零开发，纯文案位置调整。

## 5. 埋点与实验设计

### 5.1 需要新增的关键埋点事件

> 现有 `track(type, channel)` 的 `data` 恒为 `{}`，需扩展为可传 `data`；所有新事件必须加入 `server.js:336` 的 `allowed` 白名单，否则会被 400 拒绝。

| 事件名 | 触发时机 | `data` 建议字段 | 目的 |
|---|---|---|---|
| `paywall_view` | 付费墙卡片通过 `IntersectionObserver` **实际进入视口** ≥ 50% 时（每会话一次） | `{variant}` | 区分「打开页面」与「真正看到付费墙」，替代漏报的 `pro_view` |
| `plan_select` | 用户选择/切换年付或月付方案时 | `{plan}`（`annual`/`monthly`） | 测量价格呈现优化的偏好变化 |
| `checkout_start` | 点击年付/月付按钮、**即将跳转 PayPal** 时 | `{plan, variant}` | 精确替代泛化的 `pro_click`，作为实验主指标 |
| `checkout_cancel` | 从 PayPal `cancel_url` 返回但未付款时 | `{plan}` | 定位支付页流失 |
| `claim_open` | 点击「已付款领取 Pro」时 | `{}` | 识别「已付款但未开通」的阻塞 |
| `paypal_me_click` | 点击 PayPal.Me 备选入口时 | `{}` | 测量备选路径分流与意向 |
| `experiment_exposure` | 用户被分配实验分组并实际曝光标题变体时 | `{experiment, variant}` | A/B 实验分组标记，用于按变体统计 |
| `refund_request` | 用户发起退款/争议申请时 | `{reason}` | 护栏指标，监控风险逆转的真实使用率 |

**后端配套（最小改动）**
1. `server.js:336` 的 `allowed` 数组追加上述事件名；
2. `buildReport()` 增加按 `data.variant` 分组的统计字段（如 `experiments`），供 `/api/report` 出实验报表；
3. `track()` 支持第三参数 `data`，并在调用点传入变体与套餐。

### 5.2 最小 A/B 实验设计

**假设**：付费墙标题变体改变「看到付费墙 → 想点击付费」的转化意愿（主指标 `checkout_start / paywall_view`）。

| 项目 | 设计 |
|---|---|
| **分流** | 用固定 `clientId`（`GAME.clientId`，localStorage 持久化）做稳定哈希：`hash(clientId) % 2` → A（现标题）/ B（变体 A）。同一用户始终看到同一版本，避免样本污染。 |
| **分组** | 先只测 1 个变体（推荐变体 A，损失厌恶杠杆最直接），A/B 各 50%。不要同时测 3 个变体——当前流量撑不起多组。 |
| **主指标** | `checkout_start / paywall_view`（付费点击意愿） |
| **次指标** | `landing_view → paywall_view` 到达率；`checkout_start → payment` 完成率；`plan_select` 中年付占比 |
| **护栏指标** | `refund_request` 不升高；无新增投诉；页面无报错 |
| **统计口径** | 沿用后端按 `clientId` 去重（每人每阶段每天计一次，见 `server.js:255-279`），避免重复曝光虚高 |
| **结论标准** | ① 每组 `paywall_view` **≥ 100 次**且覆盖**完整一周**（消除星期效应）才看方向性差异；② 主指标相对提升 ≥ 20% 且方向稳定，才考虑全量；③ 达不到门槛就**延长实验**，不得提前宣布结论。 |
| **诚实提醒** | 当前 `proClicks` 极少、流量基数极小，**很可能数周都达不到统计显著性**。此时结论只能是「样本不足，继续观察」，不能编造「某变体胜出」。先把流量（§1 环节 1–2）做起来，实验才有意义。 |

## 6. 可直接替换的 5 个文案片段（中英对照）

### 片段 1｜替换 `pw_headline`（主标题，变体 A）
